---
title: sys.upgrades
description: "Displays the user's system upgrades"
---

((sys.upgrades)) displays information about the upgrades present on the system.

### Security Level

HIGHSEC

## Syntax

### CLI

```
sys.upgrades
```

### Script

```
#hs.sys.upgrades()
```

### Parameters

#### filter

The '((%Nfilter%))' parameter takes an object which can specify properties of the upgrade(s). Can take discrete values or some MongoDB compatible queries, e.g. `chars: { "$gte" : 2000 }`

#### full

The '((%Nfull%))' parameter takes a boolean. If the value is set to ((%Vtrue%)), ((sys.upgrades)) will display the full details object of each upgrade.

#### i

The '((%Ni%))' parameter takes either a number or an array of numbers.

#### is_script

The '((%Nis_script%))' parameter takes a boolean. If the value is set to ((%Vtrue%)), ((sys.upgrades)) returns the same output as if the script was called inside of a script.

If it is ((%Vfalse%)), it returns the same output as if the script was called from the CLI.

### Return

Returns a string, object, array of strings, or array of objects depending on the context and arguments.

#### CLI

When called from the CLI with null or invalid arguments, returns a string:

```
>>sys.upgrades
To filter list, add filter:<filter object>; e.g. filter:{loaded:true, chars:{"$gte":2000}}
full:true for upgrade details
i:<index or array> to pre-filter on index(es)

000 tier_3 chat         channel_count_v3
001 tier_3 script_space char_count_v3
002 tier_3 script_space public_script_v3
003 tier_3 script_space script_slot_v3
```

When called from the CLI with valid arguments (except ((full: true)) and integer ((%Ni%))), returns an array of strings:

```
>>sys.upgrades { filter: { } } // filter: null also does the same, and any valid filter of course.
000 tier_3 chat         channel_count_v3
001 tier_3 script_space char_count_v3
002 tier_3 script_space public_script_v3
003 tier_3 script_space script_slot_v3
```
